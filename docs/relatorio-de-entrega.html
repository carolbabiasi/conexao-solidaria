Resumo da solução

A ONG Esperança Solidária gerencia doadores e campanhas manualmente, o que limita seu crescimento. O MVP entrega uma plataforma com foco em escalabilidade, observabilidade e automação.

A decisão central da arquitetura atende ao requisito do edital de que a API não deve atualizar o valor arrecadado da campanha diretamente. Quando chega uma doação, a API grava a intenção e responde 202 Accepted. O valor arrecadado é atualizado por um Worker independente, que consome a fila de mensageria — ele é o único escritor desse campo.

Os três problemas tratados

Dupla escrita entre banco e broker

Se a API grava a doação e só depois publica o evento, uma das duas operações pode falhar sozinha. A mitigação é o Transactional Outbox: doação e evento entram na mesma transação do PostgreSQL, e o bus entrega depois.

Reentrega inflando o valor arrecadado

A entrega do broker é pelo menos uma vez. A trava é um índice único por idDoacao no ledger do MongoDB: o Worker tenta inserir e deixa o banco decidir. Se o insert falha por chave duplicada, é reentrega, e a mensagem é descartada sem somar.

Lost update entre as réplicas do Worker

Duas réplicas lendo e gravando o mesmo total fariam uma doação desaparecer. O incremento é um UPDATE atômico no PostgreSQL, nunca read-modify-write.
